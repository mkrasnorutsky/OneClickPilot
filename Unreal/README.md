# OneClickPilot — Unreal Engine migration

This is the new iOS application under construction. UE5 provides rendering and lifecycle; an independently packaged dynamic JSBSim 1.3.3 framework provides flight dynamics. The legacy FlightGear project and its fgdata resource tree are archived outside the project. Unreal uses its own bundled scenery and JSBSim model data.

## Current implementation

- UE5 C++ project, mobile forward renderer, no touch controls, no HUD/debug text.
- Single C172P-class model (`ocp172p`, project-authored), fixed 120Hz JSBSim integration and bounded catch-up.
- Fly2Gether UDP 15501/TCP 15401, original twenty-field packet, cockpit commands and six camera offsets. The default FlightGear integration in Fly2Gether is unchanged.
- Independent property store; no FlightGear core, SimGear, OSG/osgVerse or ANGLE dependency in the new project.
- Original prototype flat practice area, runway aligned approximately with EGKA 02, procedural panel with six provisional needles. These are a development scene, not the previous finished cockpit/scenery.
- Dynamic C ABI: Unreal includes no JSBSim C++ headers and owns no JSBSim C++ objects. The shared framework contains JSBSim and its adapter. Mac slices are for the editor host; iOS is the product platform.

## Build

Install Unreal Engine 5.7.4 with iOS platform support through Epic Games Launcher.

Maintenance scripts remain outside this Git repository at `../scripts` per the existing project convention:

```
python3 scripts/build_unreal_jsbsim.py
python3 scripts/unreal_project.py preflight
python3 scripts/unreal_project.py editor
python3 scripts/unreal_project.py assets
python3 scripts/unreal_project.py open
python3 scripts/unreal_project.py ios
```

Run these from the repository root. An explicit engine installation can be supplied using `--engine` or UE_ROOT. The editor/UnrealBuildTool must still validate the installed Xcode/Metal SDK combination. Generated binaries, caches and intermediate state are placed under `~/Library/Developer/OneClickPilot/Unreal-5.7.4`; framework products are under `~/Library/Developer/OneClickPilot/UnrealFlightDynamics`. ThirdParty contains ignored links to those products.

The project targets Unreal Engine 5.7.4. Its iOS Simulator target uses arm64. The JSBSim framework also provides x86_64 Simulator support for standalone backend tests.

## Validation and remaining work

Tests/check_frameworks.py verifies dynamic linkage, architectures and the eight C exports. Tests/check_controls.py builds/runs the session under sanitizers and checks the actual JSBSim control values. Tests/check_flight_dynamics.py runs the real C ABI against the Mac framework: C172 loading, flight response, engine, ground contact, invalid input, timestep bounds and lifetime. Tests/framework_smoke.cpp links/runs the Simulator framework. Tests/headless_flight.cpp runs the exact transport/session used by the UE pawn; existing Fly2Gether protocol/control checks and direct JSBSim control-property checks pass under ASan/UBSan.

Unreal Engine 5.7.4 builds with Xcode 26.6 on this Intel Mac. The Radeon RX 560 rendered the practice scene in Metal SM5 and passed the live Fly2Gether network checks. The signed iPhone 13 build rendered the scene and reported 862 RPM while parked. The signed bundle is 341,182,686 bytes. The packaging command writes the app to `~/Library/Developer/OneClickPilot/Unreal-5.7.4/Saved/StagedBuilds/IOS/OneClickPilot.app`. The map and materials were regenerated with 5.7.4 using the project bootstrap script.

The protocol store preserves electrical, radio, carb-heat and other values for controller compatibility, but their complete aircraft-system behavior is not ported. Primer is explicitly unsupported. Heading currently uses true heading as a placeholder for magnetic heading. The needles are placeholders. Full C172 cockpit/model assets, proper navigation/radios/ATIS, audio, weather, curved terrain and airport surroundings, crash handling, and comprehensive PPL maneuver comparison remain migration work.

The `ocp172p` practice model is generated by `FlightDynamics/generate_practice_model.py`. The bundled JSBSim framework retains its LGPL license. See the flight-model notes for source references and validation scope.

### Offline coastal practice area

The runway keeps the existing JSBSim origin and heading. The surrounding town,
river, waterfront and hills are fictional and generated locally by the game
mode. Repeated meshes are instanced by material. Add
`-OneClickSceneryPreview -OneClickDiagnostics` to a Mac preview launch to inspect
the layout from above. Omit both flags for the normal cockpit start.

`Editor/Textures/CoastalGrass.png` is the source for the bundled
`/Game/Materials/T_CoastalGrass` texture. It was generated using the built-in
image generation tool with this prompt:

> Create a square seamless game albedo texture for temperate coastal airfield
> grass, directly overhead orthographic photographic texture, fine irregular
> short grass and subtle straw and olive mottling at 35-meter scale, even neutral
> diffuse light, no cast shadows, no buildings no roads no writing, consistent
> edges for repeating tile.

The build cooks the imported texture and its material. The PNG is kept for
editor reimport. No external scenery downloads are used.
